The guarantees behind the data

  • OCDS 1.1 with a versioned taraba extension — LGA, method, approval body, red flags, the immutable-from timestamp and the bid commitment root. Extensions never fork the core schema.
  • Continuous releases. A release is emitted when a process changes, not in a nightly dump, so the feed can drive live alerts.
  • Validated before it leaves. A transparency claim that cannot be executed is decoration: every release is checked against the published schema before it is served, and a record that fails is withheld and listed in service status.
  • Permanent URLs. /tenders/{ocid}/ never changes. Retired paths return a permanent redirect to their successor, and the whole map is published at /redirects. Kano's re-platforming turned every previously published award list and OCDS report into a 404; that is treated here as data destruction, with a test written against it.
  • Reproducible integrity. The ledger is a hash chain over every event. You do not have to believe us — recompute it from the bulk download and compare the head hash.
  • Corrections are additive. If a record is wrong, the fix is a new event that supersedes it. The old value stays in the history, because a register whose past can be tidied is not a register.
